# 0045 — Memory: Mem0 embedding gap resolved via fastembed, no new account

**Status:** Accepted — 2026-08-26
**Component:** Memory (06)

## Context

ADR-0028 named a genuine external-credential gap: Mem0's one real differentiator over this project's own `Infrastructure`-backed adapters — `Memory.add(..., infer=True)`'s LLM-driven fact extraction and `search()`'s embedding-based similarity — needs a model provider, and this project had never chosen one anywhere. ADR-0028 deliberately deferred, naming its own resolution path: "If and when an LLM/embedding provider is chosen... Mem0 integration should be added behind its own injectable interface — most naturally as an additional, optional collaborator `DefaultEntityLinker`... could call for semantic (not just token-overlap) relatedness and confidence scoring."

ADR-0043 has since chosen an LLM provider (OpenRouter) for Agent Runtime's and Analysis & Reasoning's `reason_fn` seams. That resolves the *LLM* half of what ADR-0028 was waiting on, but not automatically the *embedding* half — ADR-0028's own Consequences flagged that "resolving one does not automatically resolve the other unless the user explicitly decides one provider should serve every component." Separately, and more directly relevant here: mem0ai's own `FastEmbedEmbedding` (`mem0/embeddings/fastembed.py`) wraps `fastembed`, a small local sentence-embedding model that runs entirely offline after its one-time download from Hugging Face Hub — no API key, no account, and this is exactly the "local/offline `fastembed` embedder" ADR-0028's own Alternatives considered section already named. The embedding half of this gap never actually needed a vendor account at all.

`EntityLinker.link(candidate: MemoryCandidate, existing: list[Memory]) -> list[str]` (the Protocol this resolves against) compares a candidate against a list the caller already retrieved and passed in — it does not need, and this decision does not build, a persistent index of its own. That rules out configuring Mem0's full `Memory` class (its own add/infer/vector-store product) as the right shape for this: ADR-0010 already decided against using Mem0 as this project's storage backend, for reasons unrelated to the provider gap, and nothing about resolving ADR-0028 reopens that.

## Decision

**Use mem0ai's own embedder abstraction directly — `EmbedderFactory`/`EmbedderConfig` configured for its `fastembed` provider — to give `EntityLinker` a second, real implementation: `Mem0EntityLinker` (`src/components/c06_memory.py`), backed by a new small module, `src/mem0_embedder.py`.** `get_embedder()` returns a memoized `FastEmbedEmbedding` instance (mem0ai's class, not a hand-rolled equivalent); `cosine_similarity(a, b)` is the standard comparison over the vectors it produces. `Mem0EntityLinker.link()` embeds the candidate's flattened content once, embeds each existing memory's flattened content, and links any memory scoring at or above `similarity_threshold` (default `0.6`).

**Model: `BAAI/bge-small-en-v1.5`**, not mem0ai's own default (`thenlper/gte-large`) — small (~130MB), fast, and capable enough for this project's actual job (deciding whether two short pieces of financial-analysis text are about the same underlying thing), where mem0ai's larger default model's extra capacity buys nothing this use case needs.

**`similarity_threshold = 0.6` is empirically grounded, not guessed.** Measured directly against this exact model before choosing it: a genuinely related pair ("AAPL stock price dropped 5 percent after earnings miss" vs. "Apple shares fell following disappointing quarterly earnings" — a pair that shares almost no tokens, the case Jaccard overlap misses entirely) scores `~0.73`; an unrelated pair (the same sentence vs. "The weather in Paris is sunny today") scores `~0.36`. `0.6` sits in the real gap between them — the same "measure it, then pick a threshold in the measured gap" method `DefaultEventObservation`'s z-score anomaly rule already used (ADR-0036), applied here to a different signal.

**`Mem0EntityLinker` is an additional, optional `EntityLinker` implementation, not the new default anywhere.** `DefaultEntityLinker` (Jaccard token overlap) stays the default for every existing caller, `DefaultLearningEvaluation` included — nothing about `update_knowledge`'s own contract or tests changes. This is a deliberate, load-bearing choice, not an oversight: loading `Mem0EntityLinker`'s embedder touches the network on a genuine first use on a given machine (the one-time model download), and this project's `Default*` classes are otherwise careful to never touch the network at construction (`DefaultInfrastructure` connects lazily, `DefaultBoundaryGate()` with no arguments never opens a connection, etc.). Silently making this the default would quietly break that invariant for every existing caller of `DefaultEntityLinker`. A caller that wants real semantic linking constructs `Mem0EntityLinker` explicitly, the same way a caller that wants OpenRouter-backed reasoning passes nothing and gets it automatically via `get_reason_fn` (ADR-0043) — the difference here is `Mem0EntityLinker` has no key-gated fallback to choose from, so the choice has to be explicit rather than automatic.

**Mem0's LLM-driven `infer=True` fact extraction/dedup is deliberately not wired in by this decision.** That capability needs Mem0's own persistent, vector-store-backed `Memory` class — a genuinely different shape than comparing a candidate against an explicitly-provided list, and the exact capability ADR-0010 already decided this project doesn't need as its storage backend. Naming this here as real, acknowledged future work (not silently done, not silently skipped) rather than overreaching this decision's actual scope.

## Alternatives considered

- **Wire in Mem0's full `Memory` class (add/infer/vector-store), using OpenRouter for its LLM and fastembed for its embedder, with a local on-disk Qdrant instance for its vector store.** Rejected: this would give `EntityLinker` a second, Mem0-owned index to keep in sync with `DefaultMemoryManager`'s own `Infrastructure`-backed store — a real consistency burden with no caller in this codebase that actually needs a second persistent index, since `link()`'s own signature already receives the full candidate list to compare against. This is exactly the mismatch ADR-0010 flagged when it decided against Mem0 as a storage backend; resolving ADR-0028 is not a reason to reopen that.
- **Use `fastembed` directly, bypassing mem0ai's package entirely.** Would work identically at the vector-math level (it's the same underlying library either way) but would misrepresent what's being resolved: ADR-0028 is specifically about Mem0's own embedding capability, and using mem0ai's own `EmbedderFactory`/`FastEmbedEmbedding` classes keeps this decision honestly scoped to what it claims to resolve, at zero real cost (mem0ai's fastembed wrapper is a thin, direct pass-through).
- **Also wire an LLM-based relatedness judgment via OpenRouter (`get_reason_fn`, ADR-0043), as a second signal alongside cosine similarity.** Considered as a natural next step given ADR-0043 already exists, but rejected for this pass as scope creep beyond what ADR-0028 asked resolved: it would mean adding a ninth `reason_fn` phase to `src/llm.py`, new prompts, and real per-call API cost to every `link()` call, for a capability real embedding similarity already covers well for this use case (see the measured 0.73/0.36 gap above). Named as real, available future work, not built here.
- **A single default threshold shared with `DefaultEntityLinker`'s Jaccard threshold (0.3).** Rejected: cosine similarity over normalized sentence embeddings and Jaccard token overlap are different metrics with different ranges and distributions — reusing Jaccard's tuned constant here would be coincidence, not a real threshold choice. `Mem0EntityLinker` measures and documents its own.
- **mem0ai's own default model (`thenlper/gte-large`).** Rejected: several times the download/inference cost of `BAAI/bge-small-en-v1.5` for no measured quality gain on the short, financial-analysis-shaped text this codebase's `MemoryCandidate.content`/`Memory.content` actually carry.

## Consequences

- `EntityLinker` now has two real implementations behind the same Protocol: `DefaultEntityLinker` (Jaccard, the unchanged default, zero dependencies beyond the standard library) and `Mem0EntityLinker` (real embedding cosine similarity, mem0ai + fastembed, network on first use only). Any caller can opt into the semantic one by constructing it explicitly — `DefaultLearningEvaluation(entity_linker=Mem0EntityLinker())`, for instance — with no Protocol or caller-contract change.
- `pyproject.toml` gains `mem0ai>=2.0` and `fastembed>=0.8` as direct dependencies (previously `mem0ai` was `uv pip install`-only, for ADR-0010's own research, never a real dependency). `uv.lock` regenerated to match. This is a real, if modest, dependency-footprint increase (`fastembed`'s own transitive dependencies include `onnxruntime`, `tokenizers`, `pillow`) for every install of this project from this point forward, not just for callers who use `Mem0EntityLinker`.
- The embedding model (~130MB) downloads once per machine on first real use of `Mem0EntityLinker` (or its own test suite) and is cached by Hugging Face Hub's own cache mechanism after that — a real, one-time network dependency this ADR's own Decision already named and justified, not hidden.
- This resolves ADR-0028's embedding-similarity half in full. The LLM-driven extraction/dedup half remains open, real future work — distinct from "unresolved," since the reason it isn't built is a genuine scope/architecture-fit call (see Alternatives), not a missing credential anymore.
- No account, API key, or external service was created or required to resolve this ADR — only local, one-time-download dependencies.
