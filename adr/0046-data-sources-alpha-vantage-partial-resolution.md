# 0046 — Data & Sources: MARKET_DATA/NEWS/EARNINGS resolved via Alpha Vantage

**Status:** Accepted — 2026-08-27
**Component:** Data & Sources (02)

## Context

ADR-0027 named the fetch-provider gap per `SourceType` without picking any vendor, since none of the options it named could be decided without the user actually choosing one and creating a real account. The user has now done exactly that for one of them: a free-tier Alpha Vantage API key (obtained directly, via a browser session this process drove with the user supplying every piece of information that required their identity — occupation category, email, and confirming the organization field) — matching this project's own `.env`-based key convention `OPENROUTER_API_KEY` (ADR-0043) already established.

Alpha Vantage's free tier genuinely covers three of `SourceType`'s seven values well: `GLOBAL_QUOTE` for a real-time quote (`MARKET_DATA`), `NEWS_SENTIMENT` for ticker-scoped news with sentiment scoring (`NEWS`), and `EARNINGS` for quarterly/annual EPS history (`EARNINGS`). It has no real equivalent for `FILING`, `REPORT`, `PRESENTATION`, or `EXTERNAL_DATASET` — ADR-0027's own alternatives section already named SEC EDGAR (no key needed at all) as the natural fit for `FILING` specifically, a separate, not-yet-built piece of future work, and flagged `REPORT`/`PRESENTATION`/`EXTERNAL_DATASET` as needing their own scoping conversation regardless of vendor.

`Source` (this component's own dataclass) carries only `id: str` and `type: SourceType` — no separate ticker/symbol field. Alpha Vantage's `symbol`/`tickers` parameters need exactly that, so this decision has to say what `source.id` means for the three source types it now serves for real.

## Decision

**`source.id` is the ticker symbol**, for `MARKET_DATA`/`NEWS`/`EARNINGS` specifically. This is the natural reading given `Source` has no other field to hold it, and it is already how every other part of this file treats `source.id` (the `_SOURCES_TABLE` row key, `retrieve_source`'s lookup key) — a plain, stable identifier for the thing being tracked, which for a market-data/news/earnings source genuinely is its ticker.

**One new module, `src/alpha_vantage_client.py`, mirroring `src/llm.py`'s and `src/mem0_embedder.py`'s existing per-vendor shape.** It is the only place in the codebase that reads `ALPHA_VANTAGE_API_KEY` or talks to Alpha Vantage's `query` endpoint. `get_api_key()` reads the key from the environment or a `.env` file at call time (never at import time, so the module stays importable and its logic unit-testable with no key present at all — same posture as `src/llm.py`'s `get_reason_fn`). `fetch_alpha_vantage(function, **params)` makes one real HTTP GET and returns the raw response body as bytes, deliberately unparsed and uninterpreted — `SourceDocument.content` is raw bytes by contract, and structurally parsing it is Data Processing & Quality's job (component 03, ADR-0032), not this module's or `AlphaVantageSourceFetcher`'s.

**`AlphaVantageSourceFetcher` added to `src/components/c02_data_sources.py`, alongside the untouched `PlaceholderSourceFetcher`.** Dispatches on `source.type` via a small lookup table (`MARKET_DATA` -> `GLOBAL_QUOTE`, `NEWS` -> `NEWS_SENTIMENT`, `EARNINGS` -> `EARNINGS`); for any other `SourceType`, delegates to `fallback` (`PlaceholderSourceFetcher` by default) rather than guessing at an unrelated vendor or raising. This is a real, honest **partial** resolution — named as such, not dressed up as complete.

**`get_source_fetcher(placeholder=None)` resolves `DefaultDataSources`'s default `SourceFetcher`**, the same selection shape `src/llm.py`'s `get_reason_fn` already established: `AlphaVantageSourceFetcher` (wrapping `placeholder` as its own fallback) when `ALPHA_VANTAGE_API_KEY` is configured, `placeholder` (`PlaceholderSourceFetcher`) unchanged otherwise. `DefaultDataSources.__init__` now defaults `source_fetcher` to `get_source_fetcher()` instead of unconditionally `PlaceholderSourceFetcher()`. Unlike `Mem0EntityLinker` (ADR-0045), constructing `AlphaVantageSourceFetcher` never touches the network — only calling `.fetch()` does — so auto-resolving this at construction time doesn't introduce the network-at-construction problem that kept `Mem0EntityLinker` an opt-in-only alternative rather than a new default.

## Alternatives considered

- **A dedicated market-data API other than Alpha Vantage (IEX Cloud, Polygon.io) as ADR-0027 also named.** Moot once the user actually created an Alpha Vantage account specifically — this decision documents the account that exists, not a fresh vendor bake-off. Alpha Vantage's free tier additionally covering `NEWS_SENTIMENT` and `EARNINGS` under the same one key (not just market data) made it cover more of ADR-0027's named gap than a market-data-only vendor would have, for the same one signup.
- **Also resolving `FILING` via SEC EDGAR in this same pass**, since ADR-0027 named it as needing no API key at all. Rejected for this pass as a separate, real piece of future work: EDGAR's fair-access policy expects a descriptive `User-Agent` header (a real, small design decision of its own — what identifies this project to EDGAR) and its full-text search response shape is different enough from Alpha Vantage's JSON that it deserves its own fetcher and its own tests, not folded into this ADR to make the resolution look more complete than the one account actually earns.
- **Guessing at `REPORT`/`PRESENTATION`/`EXTERNAL_DATASET` with Alpha Vantage's `NEWS_SENTIMENT` or `EARNINGS` endpoints anyway** (treating a presentation or a report as "close enough" to news or earnings). Rejected: these are different real capabilities Alpha Vantage's free tier does not actually provide, and ADR-0027 already flagged `EXTERNAL_DATASET` specifically as needing a real scoping conversation, not a vendor guess. `AlphaVantageSourceFetcher` delegates these to the placeholder instead of manufacturing a plausible-looking wrong answer.
- **Raising an error for source types Alpha Vantage doesn't cover, instead of delegating to a fallback fetcher.** Rejected: `SourceFetcher.fetch` returning a `SourceDocument` (even a placeholder one) is exactly what the rest of `DefaultDataSources` (`ingest_source`, `track_source_reliability_metadata`'s synthetic-content scoring) is already built to handle; raising would need new exception-handling in a caller that has no reason to change for source types this ADR doesn't touch.
- **Interpreting `source.id` as something other than a ticker (e.g., requiring a separate lookup table mapping ids to symbols).** Rejected as unnecessary complexity: nothing in this project has ever needed `Source.id` to mean anything other than the identifier a caller already uses consistently everywhere else in this file; a mapping table would solve a problem that doesn't exist yet.

## Consequences

- `DefaultDataSources()` (default constructor, no arguments) now does real market-data/news/earnings fetching when `ALPHA_VANTAGE_API_KEY` is configured — the first source type coverage in this project that isn't 100% synthetic. Without the key, behavior is completely unchanged from before this ADR: `PlaceholderSourceFetcher`, honestly synthetic, for every source type.
- `FILING`, `REPORT`, `PRESENTATION`, and `EXTERNAL_DATASET` remain exactly as open as ADR-0027 left them — this ADR does not claim to resolve them, and `AlphaVantageSourceFetcher` explicitly delegates them to the placeholder rather than silently degrading their honesty.
- `pyproject.toml` needs no new dependency — `requests` is already a direct dependency (ADR-0043).
- Existing tests that constructed `DefaultDataSources()` bare and asserted placeholder-fetcher behavior needed a real fix, not a workaround: `tests/components/test_data_sources.py` and `tests/components/test_learning_evaluation.py` both gained an `autouse` fixture that clears `ALPHA_VANTAGE_API_KEY` and redirects `alpha_vantage_client._ENV_FILE_PATH` to a nonexistent file for every test in those files by default — the same isolation `tests/test_llm.py`'s `_no_env_key` helper already established for `OPENROUTER_API_KEY`, applied here so this repo's own real `.env` key (needed for actual use) doesn't make those tests' bare-default assertions machine-dependent. `tests/components/test_retrieval_context.py` needed no change — both of its `DefaultDataSources` constructions already pass an explicit `source_fetcher`.
- The key itself lives only in `.env` (gitignored, never committed) — nothing in this ADR, the code, or the tests hardcodes it.
